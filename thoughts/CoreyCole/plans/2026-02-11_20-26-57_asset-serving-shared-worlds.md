# Shared Asset Serving Implementation Plan

## Overview

Set up the infrastructure for serving shared assets from the harness to all Bevy/WASM game worlds. This enables multiple game worlds to load the same assets (models, textures, audio) via HTTP from a single `/assets` endpoint, with browser cache sharing across same-origin iframes. Must work identically in local development (`http://localhost:8080`) and cloud deployment (`https://creative-mode.example.com`).

## Current State Analysis

**Already in place:**
- `/assets` static route at `server.go:103` — public, serves from `{DataDir}/shared-assets/`
- WASM iframes are same-origin with the harness (served from the same Echo server)
- `template/CLAUDE.md` documents the intended asset loading pattern
- Client reads URL params via `web_sys` (pattern to follow at `client/src/main.rs:116-134`)

**What's missing:**
- `data/shared-assets/` directory is never created
- No `AssetMetaCheck::Never` on `AssetPlugin` (causes 404 spam for `.meta` files on WASM)
- No `AssetPlugin.file_path` override (default `"assets"` resolves to wrong path inside iframe)
- No `Cache-Control` headers on `/assets` route
- No MIME type handling for game-specific formats (`.glb`, `.ktx2`)
- No test asset to verify the pipeline

### Key Discoveries:
- `server.go:103`: route exists but directory doesn't — Echo returns 404 for all `/assets/*` requests
- `main.go:30`: only `dataDir` itself is created via `MkdirAll`, subdirectories like `shared-assets/` are not
- `client/src/main.rs:34-42`: `DefaultPlugins` only customizes `WindowPlugin`, `AssetPlugin` uses all defaults
- `client/Cargo.toml:7`: Bevy `"https"` feature is NOT enabled (not needed for our approach)
- `server.go:88-104`: `/assets` route is registered before auth middleware — public access works

### Verified via Web Research:
- **`file_path: "/assets"` confirmed working on WASM** — `HttpWasmAssetReader` uses `PathBuf::join` → `/assets/textures/foo.png` → `window.fetch_with_str()` → browser resolves absolute path from origin root ([Bevy source: `bevy_asset/src/io/wasm.rs`](https://github.com/bevyengine/bevy/blob/v0.18.0/crates/bevy_asset/src/io/wasm.rs))
- **Same-origin iframes share browser cache** in all modern browsers (Chrome 86+, Firefox 85+, Safari). Cache partitioning only affects cross-site frames. ([Chrome cache partitioning](https://developer.chrome.com/blog/http-cache-partitioning))
- **`AssetMetaCheck::Never` is a field on `AssetPlugin`** in Bevy 0.18, not a separate resource. Issue [#18002](https://github.com/bevyengine/bevy/issues/18002) confirms it's NOT the default on WASM — must be set explicitly.
- **Bevy uses Fetch API, not XHR** — `window.fetch_with_str()` under the hood. Good for WASM code caching.
- **Go's `http.ServeContent` (used by Echo `c.File()`) automatically handles `Last-Modified` and `If-Modified-Since`** — 304 responses work for free. No manual ETag needed.
- **Echo v4 `e.Static()` has no cache header config** — must use custom handler or group+middleware ([Echo issue #1902](https://github.com/labstack/echo/issues/1902)).

## Desired End State

After implementation:
1. `data/shared-assets/` is auto-created on harness startup
2. A seed test texture (programmatic checkerboard PNG) is generated on first run
3. The Bevy client `AssetPlugin` is configured with `file_path: "/assets"` and `AssetMetaCheck::Never`
4. The template's ground plane loads the test texture from `/assets/textures/test-checkerboard.png`
5. The `/assets` route returns appropriate `Cache-Control` and MIME type headers
6. Multiple world iframes loading the same asset URL share browser cache (verified by network tab)

**Verification**: Open two different worlds, observe in the browser network tab that the second world's asset request returns `304 Not Modified` or is served from disk cache.

## What We're NOT Doing

- Content-addressed filenames (hash in filename + manifest) — future optimization
- CDN integration or separate asset origin — harness serves directly for now
- Brotli/gzip compression middleware — `.glb` compresses ~60% but can be added later
- Per-world custom assets — all assets are shared across all worlds
- Asset upload UI — assets are manually placed or generated by code
- The `https` Bevy feature — not needed since we use same-origin relative paths
- Service Worker or IndexedDB caching — browser HTTP cache is sufficient
- `load_folder()` support — not available on WASM (no directory listing over HTTP)

## Implementation Approach

**Approach B: `AssetPlugin.file_path = "/assets"`** — confirmed working via Bevy source code analysis:

- `HttpWasmAssetReader` uses `PathBuf::join(root_path, asset_path)` → absolute path from origin root
- `window.fetch_with_str("/assets/textures/foo.png")` → browser resolves from origin
- Works identically on `http://localhost:8080` and `https://creative-mode.example.com`
- No need to derive harness origin, pass URL params, or enable the `https` Bevy feature

```go
func seedSharedAssets(dir string) {
    texturesDir := filepath.Join(dir, "textures")
    _ = os.MkdirAll(texturesDir, 0o750)

    testPath := filepath.Join(texturesDir, "test-checkerboard.png")
    if _, err := os.Stat(testPath); err == nil {
        return // already seeded
    }

    img := image.NewRGBA(image.Rect(0, 0, 16, 16))
    for y := range 16 {
        for x := range 16 {
            if (x/4+y/4)%2 == 0 {
                img.Set(x, y, color.RGBA{R: 200, G: 200, B: 200, A: 255})
            } else {
                img.Set(x, y, color.RGBA{R: 80, G: 80, B: 80, A: 255})
            }
        }
    }

    f, err := os.Create(testPath)
    if err != nil {
        log.Printf("Warning: failed to seed test asset: %v", err)
        return
    }
    defer f.Close()
    _ = png.Encode(f, img)
}
```

Required imports: `"image"`, `"image/color"`, `"image/png"`.

#### 3. Replace `e.Static("/assets", ...)` with custom handler
**File**: `harness/internal/server/server.go`
**Changes**: Replace line 103 with a custom handler that adds `Cache-Control` headers, game-specific MIME types, and path traversal protection (consistent with `handleWASMArtifacts` pattern).

Replace:
```go

```

With:
```go

```

Add new handler method:
```go
// handleSharedAssets serves files from data/shared-assets with cache and MIME headers.
func (s *Server) handleSharedAssets(c echo.Context) error {
    filePath := c.Param("*")

    baseDir := filepath.Join(s.DataDir, "shared-assets")
    fullPath := filepath.Clean(filepath.Join(baseDir, filePath))
    if !strings.HasPrefix(fullPath, filepath.Clean(baseDir)+string(os.PathSeparator)) {
        return echo.NewHTTPError(http.StatusBadRequest, "invalid path")
    }

    if _, err := os.Stat(fullPath); os.IsNotExist(err) {
        return echo.NewHTTPError(http.StatusNotFound, "asset not found")
    }

    // Set MIME types for game-specific formats not in Go's default registry.
    ext := strings.ToLower(filepath.Ext(fullPath))
    switch ext {
    case ".glb":
        c.Response().Header().Set("Content-Type", "model/gltf-binary")
    case ".gltf":
        c.Response().Header().Set("Content-Type", "model/gltf+json")
    case ".ktx2":
        c.Response().Header().Set("Content-Type", "image/ktx2")
    }

    // In production, enable browser caching with background revalidation.
    // Go's http.ServeFile (via c.File) automatically handles Last-Modified
    // and If-Modified-Since for 304 responses.
    if os.Getenv("DEV_MODE") != "true" {
        c.Response().Header().Set("Cache-Control", "public, max-age=3600, stale-while-revalidate=86400")
    }

    return c.File(fullPath)
}
```

**Cache strategy rationale:**
- `max-age=3600` — fresh for 1 hour (no network request at all)
- `stale-while-revalidate=86400` — for the next 24 hours after expiry, serve stale immediately and revalidate in background. Eliminates revalidation latency for returning players.
- Dev mode has no `Cache-Control` — assets always revalidate so changes are visible immediately (Go still sends `Last-Modified`, so unchanged files get 304).
- Go's `c.File()` → `http.ServeContent()` automatically sets `Last-Modified` from file mtime and handles `If-Modified-Since` → 304 responses.

**MIME type rationale:**
- Go's `mime.TypeByExtension` doesn't know `.glb`, `.gltf`, or `.ktx2`
- `.wasm` (`application/wasm`) and `.png` (`image/png`) are handled correctly by Go's defaults
- Correct MIME types are important: `.wasm` needs `application/wasm` for V8 streaming compilation and code caching

## Performance Considerations

- **16x16 test texture is intentionally tiny** — just proves the pipeline works. Real assets will be larger.
- **No compression middleware yet** — `.glb` files compress ~60% with gzip, `.ktx2` and `.ogg` are already compressed. Can add Echo gzip middleware later with exclusions for pre-compressed formats.
- **`stale-while-revalidate`** eliminates revalidation latency for returning players — asset loads feel instant even after `max-age` expires.
- **Browser cache sharing** — same-origin iframes confirmed to share cache in Chrome 86+, Firefox 85+, Safari. N worlds loading the same texture = 1 network request.
- **Go's `Last-Modified` / 304 support is automatic** — `c.File()` → `http.ServeContent()` sets `Last-Modified` from file mtime and handles conditional requests for free.

## Cloud Deployment Notes

This implementation works in cloud deployment without changes because:

1. **Same-origin guarantee**: The WASM iframe (`/wasm/{worldID}/{cpID}/index.html`) and the asset endpoint (`/assets/*`) are both served from the same harness server. Whether at `localhost:8080` or behind a reverse proxy at `https://creative-mode.example.com`, the origin is the same.

2. **No hardcoded URLs**: The `file_path: "/assets"` approach uses origin-relative paths. The browser resolves `/assets/...` against whatever origin served the page.

3. **TLS transparent**: A reverse proxy (Nginx, Caddy, Cloudflare) terminates TLS; the harness still serves plain HTTP on `:8080`. The browser sees `https://` for both the page and the asset request — same origin.

4. **Cache-Control is conditional**: Dev mode skips caching headers. Production gets `max-age=3600, stale-while-revalidate=86400`.

5. **`data/shared-assets/`**: In cloud deployment, this directory is on the server's filesystem. Operators place assets there. The seed function creates the test texture on first run.
