### Step 2: Register migration in `db.go`

### Step 3: Add `PRAGMA synchronous=NORMAL`

In `db.go`, after the `busy_timeout` PRAGMA block (line 48), add:

```go
// With WAL mode, NORMAL sync is safe and reduces fsync calls.
if _, err := sqlDB.ExecContext(ctx, "PRAGMA synchronous=NORMAL"); err != nil {
    _ = sqlDB.Close()
    return nil, fmt.Errorf("setting synchronous mode: %w", err)
}
```

### Step 4: Wrap migration execution in transactions

In `db.go`'s `runMigrations` method, replace the bare `ExecContext` + `INSERT` (lines 131-144) with a transaction-wrapped version:

```go
content, err := migrations.ReadFile(file)
if err != nil {
    return fmt.Errorf("reading %s: %w", file, err)
}

tx, err := d.db.BeginTx(ctx, nil)
if err != nil {
    return fmt.Errorf("beginning tx for %s: %w", file, err)
}
if _, err := tx.ExecContext(ctx, string(content)); err != nil {
    _ = tx.Rollback()
    return fmt.Errorf("executing %s: %w", file, err)
}
if _, err := tx.ExecContext(ctx,
    "INSERT INTO _migrations (name) VALUES (?)", file,
); err != nil {
    _ = tx.Rollback()
    return fmt.Errorf("recording migration %s: %w", file, err)
}
if err := tx.Commit(); err != nil {
    return fmt.Errorf("committing %s: %w", file, err)
}
```

**Note**: All current migrations are DDL (CREATE TABLE/INDEX, ALTER TABLE) which work inside SQLite transactions. PRAGMA statements are not used in any migration file — they are set in the `New()` function before migrations run.

- **Transaction wrapping is forward-only**: Existing migrations are not re-run. This fix only protects future migrations from crash inconsistency. Acceptable — all existing migrations have already been applied.
- **GetMayorMessages signature change**: The `Querier` interface will change, but the only callers are in `mayor_dashboard.go` (2 call sites). No mocks or test doubles implement `GetMayorMessages` — verified via grep. Low risk.
