# Swarm Code PR Skill

Creates a git branch, commits changes, pushes, and opens a GitHub PR linked to the Linear ticket.

## Preamble

1. If `$CM_SWARM_HANDOFF_PATH` is set, read the handoff document from verify phase (approval context).
2. If `$CM_SWARM_LEARNING_CONTEXT_PATH` is set, read it for relevant learnings.
3. Load `swarm-conventions` for comment format and document path conventions.

## Environment

| Variable | Purpose |
|----------|---------|
| `CM_SWARM_TICKET_ID` | Ticket identifier (e.g., `CM-123`) |
| `CM_SWARM_WORKFLOW_ID` | Workflow UUID |
| `CM_SWARM_SESSION_ID` | Session UUID |
| `CM_SWARM_PHASE` | Should be `pr` |
| `CM_SWARM_HANDOFF_PATH` | Handoff from verify phase |
| `CM_SWARM_LEARNING_CONTEXT_PATH` | Learning context file |
| `CM_SWARM_RESULT_PATH` | Path to write RESULT output as final action |
| `CM_SWARM_DRY_RUN` | If `true`, no git/GitHub operations |
| `CM_SWARM_BRANCH` | Branch name (if pre-set by orchestrator) |

## Process

1. **Determine branch name** — Use `$CM_SWARM_BRANCH` if set, otherwise:
   - Format: `swarm/{ticketID}/{slug}`
   - Slug: sanitized ticket title (lowercase, hyphens, max 50 chars)

2. **Read the plan** — Find the approved plan to extract:
   - Ticket title for PR title
   - File inventory for PR description
   - Acceptance criteria for test plan

3. **Create branch and commit**:
   ```bash
   git checkout -b swarm/{ticketID}/{slug}
   git add {specific files from plan's file inventory}
   git commit -m "{ticket title}

   {Brief description of changes}

   Closes {ticketID}"
   ```
   - Stage specific files, not `git add -A`
   - Include handoff and plan documents in the commit

4. **Push to remote**:
   ```bash
   git push -u origin swarm/{ticketID}/{slug}
   ```

5. **Create GitHub PR** — Use `gh pr create`:
   ```bash
   gh pr create --title "{ticketID}: {title}" --body "$(cat <<'EOF'
   ## Summary
   - {bullet points from plan}

   ## Changes
   {file inventory from plan}

   ## Test plan
   - [ ] `just check` passes
   - [ ] {verification checks from plan}

   Closes {ticketID}

   🤖 Generated by swarm agent
   EOF
   )"
   ```

6. **Move ticket to In Review** — Update Linear ticket status:
   ```bash
   linear-cli update {ticketID} --status "In Review"
   ```

7. **Post Linear comment** — `PR:` prefix:
   ```
   PR: {PR URL}
   Branch: swarm/{ticketID}/{slug}
   Files: {count} changed
   ```

8. **Write handoff** — Write handoff to `thoughts/swarm/handoffs-code/`.

9. **Write RESULT**:
   ```
   RESULT: success
   Phase: pr
   Handoff: thoughts/swarm/handoffs-code/{filename}

   Summary: Opened PR {URL} with {N} files changed
   ```

## Dry-Run Mode

If `$CM_SWARM_DRY_RUN` is `true`:
- Print `[DRY-RUN]` before each action
- Do NOT create branches, commit, push, or create PRs
- Do NOT update Linear ticket status
- Still read files and describe what would be done

## Error Handling

- If `git push` fails → `RESULT: infra_failure` (auth or network issue)
- If `gh pr create` fails → `RESULT: infra_failure`
- If Linear update fails → log warning, continue (PR is more important)
- If interrupted → write partial handoff with branch/PR state

## Result File Output

As the very last step, if `$CM_SWARM_RESULT_PATH` is set, write the RESULT block to that file path (in addition to any Linear comment).
