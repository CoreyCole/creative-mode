# Research: HTTP Hardening — Body Limits, Security Headers, Admin-Gate Swarm, Auth Logging

## Questions

1. What is the current state of HTTP security in the harness server?
2. How should body limits, security headers, and admin gating be implemented?
3. Where should failed auth attempts be logged with source IPs?
4. What existing patterns and constraints should guide the implementation?

## Findings

### 1. Current Middleware Stack (server.go:110-123)

The `RegisterRoutes` method currently applies only two middleware globally:

```go
e.Use(middleware.RequestLoggerWithConfig(...))
e.Use(middleware.Recover())
```

No body limits, no security headers, no rate limiting. The `middleware` package from `github.com/labstack/echo/v4/middleware` is already imported.

### 2. Body Limits — Echo Has Built-In Support

Echo provides `middleware.BodyLimit("10M")` out of the box. This is a single line addition:

```go
e.Use(middleware.BodyLimit("10M"))
```

**Placement**: Should go right after `middleware.Recover()` in `RegisterRoutes`, before any route registration. This applies globally to all POST/PUT/PATCH requests.

**Consideration**: SSE endpoints use long-lived GET connections (no body), so body limits won't interfere with them. The `/api/world-hatched` webhook sends cover art as base64 (can be several MB), so 10M is appropriate. The `/api/assets/upload` endpoint also needs reasonable limits.

### 3. Security Headers — Echo Has Built-In `SecureWithConfig`

Echo provides `middleware.SecureWithConfig()` which sets all standard security headers:

```go
e.Use(middleware.SecureWithConfig(middleware.SecureConfig{
    XSSProtection:         "1; mode=block",
    ContentTypeNosniff:    "nosniff",
    XFrameOptions:         "DENY",
    HSTSMaxAge:            31536000,
    ContentSecurityPolicy: "",     // leave empty — game iframes need flexibility
    ReferrerPolicy:        "strict-origin-when-cross-origin",
}))
```

**Key decisions**:
- **X-Frame-Options: DENY** (project plan says DENY). However, the harness serves game iframes (`/world/:worldID/:cpID/trunk/*` and `/wasm/:worldID/:cpID/*`). These are loaded within the harness UI via `<iframe>`. Since the iframe source is the same origin (or a proxied route), `DENY` will block them. We should use **SAMEORIGIN** instead to allow same-origin iframes while blocking third-party framing.
- **HSTS max-age: 31536000** (1 year). The harness runs behind Caddy on EC2 (public site) and directly via Tailscale on VPS. Both use HTTPS. HSTS is safe.
- **No CSP for now**: The game iframes, Datastar, and inline event handlers make CSP complex. Deferred.

### 4. Admin-Gating Swarm Dashboard Actions

**Current state** (server.go:219-221): Swarm dashboard gate/cancel routes are in the `approved` group:

```go
approved.POST("/swarm/:id/cancel", s.handleSwarmDashboardCancel)
approved.POST("/swarm/:id/approve", s.handleSwarmDashboardApprove)
approved.POST("/swarm/:id/reject", s.handleSwarmDashboardReject)
```

These allow **any approved user** (not just admins) to approve/reject/cancel swarm workflows. This is a security issue — swarm gate actions should be admin-only.

**Implementation**: Move these three routes from the `approved` group to a new admin subgroup within the authed group. The existing `auth.AdminMiddleware()` is already used for `/admin/users`.

Two options:
- **Option A**: Create a new `adminGroup` under the `authed` group for swarm admin actions
- **Option B**: Add the routes to the existing `/admin` group (but paths would change to `/admin/swarm/:id/approve` etc.)

**Recommendation**: Option A — keep the `/swarm/:id/` URL path prefix (no breaking change for the frontend) but add `auth.AdminMiddleware()` to those specific routes. Create a sub-group:

```go
// Swarm dashboard — read-only views (approved users)
approved.GET("/swarm", s.handleSwarmDashboard)
approved.GET("/swarm/events", s.handleSwarmDashboardSSE)
approved.GET("/swarm/:id", s.handleSwarmWorkflowDetail)
// ... other GET routes stay in approved

// Swarm dashboard — mutation actions (admin only)
swarmAdmin := authed.Group("/swarm", auth.AdminMiddleware())
swarmAdmin.POST("/:id/cancel", s.handleSwarmDashboardCancel)
swarmAdmin.POST("/:id/approve", s.handleSwarmDashboardApprove)
swarmAdmin.POST("/:id/reject", s.handleSwarmDashboardReject)
```

**Note**: The `authed` group already has `auth.SessionMiddleware(s.DB)` which sets `c.Get("user")`. The `auth.AdminMiddleware()` checks `user.Role == "admin"`. This chain is: session check → admin check → handler.

### 5. Auth Failure Logging with Source IP

Three auth middlewares need logging on failure:

**a) `hookSecretMiddleware()` (server.go:714-724)**
Currently returns 403 silently. Should log with source IP.

**Challenge**: `hookSecretMiddleware()` is a package-level function (not a method on Server), so it doesn't have access to `s.Logger`. Two options:
- Accept `*slog.Logger` as a parameter
- Use `slog.Default()` or `c.Logger()` (Echo's logger)
- Make it a method on Server

**Recommendation**: Pass `*slog.Logger` as a parameter since the function is called during route registration where `s.Logger` is available:

```go
func hookSecretMiddleware(logger *slog.Logger) echo.MiddlewareFunc {
    secret := os.Getenv(swarm.EnvKey("HookSecret"))
    return func(next echo.HandlerFunc) echo.HandlerFunc {
        return func(c echo.Context) error {
            if secret != "" && c.Request().Header.Get("X-Hook-Secret") != secret {
                logger.Warn("hook secret auth failed",
                    "ip", c.RealIP(),
                    "path", c.Path(),
                )
                return echo.NewHTTPError(http.StatusForbidden, "invalid hook secret")
            }
            return next(c)
        }
    }
}
```

**b) `presidentAuthMiddleware()` (president_api.go:20-36)**
Currently returns 403 silently on invalid secret. Should log with source IP.

Same pattern: accept `*slog.Logger` as a parameter.

```go
func presidentAuthMiddleware(logger *slog.Logger) echo.MiddlewareFunc {
    // ... existing logic ...
    if c.Request().Header.Get("X-President-Secret") != secret {
        logger.Warn("president auth failed",
            "ip", c.RealIP(),
            "path", c.Path(),
        )
        return echo.NewHTTPError(http.StatusForbidden, "invalid president secret")
    }
}
```

**c) `s.mayorAuthMiddleware` (mayor_api.go:83-101)**
This is already a method on Server, so it has `s.Logger`. Currently returns 401/403 silently. Should log:

```go
func (s *Server) mayorAuthMiddleware(next echo.HandlerFunc) echo.HandlerFunc {
    return func(c echo.Context) error {
        secret := c.Request().Header.Get("X-Mayor-Secret")
        if secret == "" {
            s.Logger.Warn("mayor auth failed: missing secret",
                "ip", c.RealIP(),
            )
            return echo.NewHTTPError(http.StatusUnauthorized, "missing mayor secret")
        }
        w, err := s.DB.GetWorldByMayorSecret(...)
        if err != nil {
            s.Logger.Warn("mayor auth failed: invalid secret",
                "ip", c.RealIP(),
            )
            return echo.NewHTTPError(http.StatusForbidden, "invalid mayor secret")
        }
        // ...
    }
}
```

**IP extraction**: Echo's `c.RealIP()` returns the client IP, respecting `X-Forwarded-For` and `X-Real-Ip` headers. This is appropriate since the harness runs behind Caddy (on EC2) and Tailscale Serve (on VPS), both of which set forwarding headers.

### 7. X-Frame-Options SAMEORIGIN vs DENY

The project plan says DENY, but the harness UI loads game content in iframes:

- `handleTrunkProxy` serves Trunk WASM content at `/world/:worldID/:cpID/trunk/*`
- `handleWASMArtifacts` serves static WASM at `/wasm/:worldID/:cpID/*`
- The `worldview.Page()` template renders an `<iframe>` pointing to these routes

With `X-Frame-Options: DENY`, the browser would refuse to render the iframe content since DENY blocks all framing — even same-origin. `SAMEORIGIN` allows the harness to frame its own content while preventing third-party sites from framing harness pages.

**Recommendation**: Use `SAMEORIGIN` instead of `DENY`.

### 8. Existing Import Analysis

`server.go` already imports `github.com/labstack/echo/v4/middleware`. No new dependencies needed. The `middleware.SecureWithConfig` struct is in the same package. `slog` is already imported in `server.go`. `president_api.go` will need to add `slog` import.

## Architecture Notes

- The Echo middleware stack executes in registration order. `BodyLimit` should go early (after Logger and Recover) to reject oversized requests before they're parsed.
- `SecureWithConfig` should go early too — it sets response headers that should be present on all responses, including error pages.
- The `hookSecretMiddleware()` is called 4 times in `RegisterRoutes` (claude-event, world-hatched, and twice via `swarmGroup`). Changing its signature to accept a logger requires updating all call sites.
- The swarm dashboard GET routes (viewing workflows, events, metrics) should remain accessible to all approved users — only mutation actions (approve/reject/cancel) need admin gating.

## Risks and Considerations

1. **X-Frame-Options SAMEORIGIN vs DENY**: Using DENY as the plan suggests will break game iframes. Must use SAMEORIGIN. This deviates from the plan but is correct.
2. **HSTS and dev mode**: HSTS with a 1-year max-age on a dev server could be annoying if someone accesses it over HTTP. Should skip HSTS when `DEV_MODE=true` or set a shorter max-age. The middleware's `Skipper` field can conditionally skip.
3. **hookSecretMiddleware signature change**: Passing `logger` changes the function signature at 4 call sites. Alternatively, could use `slog.Default()` to avoid signature changes, but explicit dependency injection is cleaner.
4. **Admin-gating swarm routes**: The swarm dashboard UI currently shows approve/reject/cancel buttons to all users. After gating, non-admin users will see buttons that return 403. The UI should hide these buttons for non-admin users, but that's a frontend change beyond this ticket's scope. The backend gating is the priority.

## Recommendations

1. Add `middleware.BodyLimit("10M")` and `middleware.SecureWithConfig(...)` to `RegisterRoutes` after the existing middleware.
2. Use `X-Frame-Options: SAMEORIGIN` (not DENY) to support game iframes.
3. Skip HSTS in dev mode to avoid sticky redirects during development.
4. Move `/swarm/:id/cancel`, `/swarm/:id/approve`, `/swarm/:id/reject` behind `auth.AdminMiddleware()`.
5. Update `hookSecretMiddleware()` and `presidentAuthMiddleware()` to accept `*slog.Logger` and log failures with `c.RealIP()`.
6. Add auth failure logging to `s.mayorAuthMiddleware`.
7. All changes are in 3 files in `harness/internal/server/`.
